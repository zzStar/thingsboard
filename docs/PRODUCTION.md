# 设备产量

入口为“监控 → 设备产量”，或设备详情顶部的“查看产量”；设备列表也提供产量图标。当前 PE 设备详情使用通用分组标签组件，入口已放在实际使用的 DeviceComponent 中。页面使用现有设备读取权限；租户管理员和普通客户用户均可使用全部产量功能，具体操作仍检查相应设备权限，客户身份本身不再限制设置、回算或大屏链接管理。

每台设备可单独配置单位：有相应权限的租户管理员或客户用户选择设备，点击顶部“设置单位”或“单位与班次”标签，填写产量单位（例如贴、件、页、米）并保存，单位名称立即生效。班次调整才使用未来生效生产日期。配置按设备落库，互不影响；产量、速度、历史报表及导出统一使用该设备当前单位名称，数量不换算。保存后管理页主动刷新，大屏在下一次5秒轮询时更新，无须更换大屏链接。

旧版本已经保存到待生效配置中的单位修改也按最新名称显示，不必等到班次生效日期。更新单位不会新增统计边界或重算产量；原有班次及配置生效时刻保留。

## 客户用户的权限配置

客户账号仍为`CUSTOMER_USER`，无需改成租户管理员。前后端已允许两种身份使用相同的产量功能；是否能对某设备执行操作，由该账号的角色权限及设备所属/共享范围共同决定。

| 功能 | 设备权限 |
|---|---|
| 选择设备、加载设备信息 | `READ` |
| 概览、速度、历史查询与导出、查看回算进度 | `READ_TELEMETRY` |
| 保存单位、班次与时区设置 | `WRITE_ATTRIBUTES` |
| 生成、读取、复制、重置、停用大屏链接 | `READ_TELEMETRY` + `WRITE_ATTRIBUTES` |
| 发起历史回算 | `WRITE_TELEMETRY` |

要完整开放产量功能，可创建“组”类型角色，勾选`READ`、`READ_TELEMETRY`、`WRITE_ATTRIBUTES`、`WRITE_TELEMETRY`，再将其绑定到客户用户组，目标选择该客户的设备组。只读角色仍不能保存设置、发起回算或管理大屏链接；无读取权限的设备不会出现在选择器中。保存授权后重新登录，继续沿用平台现有租户/客户及设备组隔离，不自动给账号添加全局权限。

## 每设备永久大屏链接

独立大屏顶部不显示平台 Logo；主标题显示设备当前所属客户的名称（`customer.title`），副标题保留设备名称。未归属客户时显示“未分配客户”，客户改名或设备归属变化在下次5秒轮询时更新，无须重新生成链接。客户名称仅关联设备同租户的客户，断连快照也保留最近成功读取的名称；旧快照缺少该字段时显示加载提示并等待接口刷新。

有相应权限的租户管理员或客户用户选择设备后，在“产量看板”上方点击“生成大屏链接 → 复制链接”，将完整链接配置到这台设备的大屏。链接格式为 `/production-screen/<设备ID>#key=<独立随机密钥>`，复制时须保留 `#` 后的部分。公开页使用独立路由，无登录框、侧栏、设备切换、设置、历史查询及写入功能；看板与管理页共用显示组件，展示速度、今日/本周/本月、各班产量及趋势。

每台设备保留一个链接，重复生成返回原链接。访问密钥使用32字节安全随机数，与设备和租户绑定，保存在 PostgreSQL 的 `production_screen_link` 表中，没有到期时间；应用重启、普通发版、管理员退出和登录 JWT 过期都不会使链接失效。链接管理接口允许租户管理员和客户用户使用，同时检查设备遥测读取与属性写入权限。授权用户可“重置链接”或“停用链接”，旧链接随即无法继续请求数据；设备删除级联删除链接，设备转移到其他租户后旧链接也不能读取数据。

浏览器每5秒请求一次只读快照，服务器固定返回该设备看板所需数据。公开接口为 `GET /api/noauth/production/<设备ID>/screen`，密钥通过 `X-Production-Screen-Key` 请求头发送，成功响应禁止缓存；此密钥不能调用登录后的产量设置、回算、设备遥测或其他管理接口。密钥放在 URL fragment 中，不随页面 URL 请求发送给服务器。

设备停止上报仍从数据库读取产量及历史趋势，显示等待设备恢复上报的提示，仅将过期实时速度显示为不可用。速度曲线查询异常或超时不阻断产量与历史，返回单独提示，同一生产日已有的曲线继续保留。看板每次成功读取后保存最近快照到浏览器，连接中断时显示重连和完整上次更新时间；刷新页面也可恢复该设备、该链接的最近快照，自动重试。首次访问且接口不可达时保留看板框架、未知数值显示为“—”，待接口恢复后自动显示真实历史，不将未知产量显示为0。浏览器快照按设备与链接密钥哈希隔离，不保存原始密钥；禁止浏览器存储时仍保留当前页面内存数据。链接被重置或停用时显示不可用并清除看板及对应缓存。支持全屏和 iframe 嵌入，当前默认 HTTP 安全头允许嵌入；若部署方另外启用了 X-Frame-Options 或 CSP frame-ancestors，需要允许实际大屏平台的来源。

## 默认口径

- `totalCount` 是工单计数器，单位默认“贴”；`speed` 是速度，默认“贴/小时”。单位名称可配置，只改变展示名称，不执行数值换算。
- 默认白班07:30–19:30、夜班19:30–次日07:30，上报间隔2秒。支持两班、三班，班次名称和开始时间可编辑；每班结束时间为下一班开始时间，连续覆盖24小时。
- 首班开始时间是生产日边界。跨日班次归开始日，周一是每周起点，月统计按生产日期归属。
- 班次、时区及上报间隔配置从未来生产日生效，以修改前的生产日边界作为生效瞬间。历史班次配置保留；改变首班开始时间时，过渡生产日可能缩短或延长，实际统计时段会显示在报表中。单位名称独立立即生效，历史报表也同步更新名称。

## 计数与精度

处理接在 `DefaultTelemetrySubscriptionService` 的历史遥测保存成功之后；只有设备的 `totalCount` 参与计算，无须调整设备上报协议或规则链。没有保存历史遥测的策略不触发产量持久化。

首次读数建立基线，不将既有计数归入当天。正常增量为本次计数减前次计数；计数下降按清零处理，增量为本次计数。现场已确认停机、清零、重新开工所需时间远大于2秒，因此以计数下降识别清零。即便上报到了零，也无法从计数器本身恢复最后一次上报后、清零前未上报的尾数；原始遥测完整性仍决定统计精度。

PLC短暂归零有额外校验：已知非零计数之后连续上报零，并在一个配置上报周期内（默认严格小于2秒，最长10秒）恢复到**完全相同**的旧读数时，整段视为无效采集，不将恢复的旧计数计入新增产量，也不增加清零次数。按经过时间判断，不按零值条数判断；例如7条零值发生在352毫秒内仍属于短暂归零。原始计数和时间保留，这段覆盖时间标记为缺口。持续达到确认窗口的零值、出现不同的非零新读数、没有已知基线的首次读数，均不按此规则排除。本规则依赖现场确认的清零/重新开工时长；若设备确实能在窗口内清零并生产到完全相同的旧计数，仅靠计数器无法区分，需采集PLC数据有效/复位状态。

设备读数必须是非负整数；同设备、同时间戳防重。显式允许覆盖的遥测可以修正已有读数；普通重试不覆盖。迟到读数会修正其自身和后继读数的增量，并重新校验周围短暂归零事件，在同一数据库事务中调整分钟、班次和每日汇总。回算与自动修复复用同一规则，重新导入未改变的原始计数也会修正旧版本误算的增量。每设备数据库行锁支持并发写入；基线由持久化读数恢复，应用重启不会把当前计数全部重复计入。

统计范围为开始包含、结束不包含。增量发生于相邻上报时间之间。切到查询、交班或分钟边界时，以累计比例的整数差分分配，确保连续区间合计等于原增量，不产生小数或重复计数。跨越查询或交班边界的正增量显示“含边界估算”。超过 `max(10秒, 3倍上报间隔)` 的采样间隔标为缺口；停机但持续上报同一计数时，产量为零且数据有效。

## 存储

启动时在同一PostgreSQL数据库执行幂等的 `application/src/main/resources/production-schema.sql`。初始化由事务级咨询锁保护，不修改已有ThingsBoard表结构。安装模式不加载产量服务，首次正常启动时建立扩展表。

| 表 | 粒度与内容 |
| --- | --- |
| `production_device` | 每设备的事务锁、租户及处理版本 |
| `production_screen_link` | 每设备一个永久只读大屏密钥、所属租户和创建时间；随设备删除清理 |
| `production_config` | 每设备、每个生效时间的配置版本 |
| `production_sample` | 每次有效计数上报；计数、前次时间、增量、清零和缺口标记，正常约2秒 |
| `production_minute` | 每设备、每分钟；产量、有效/缺口覆盖时间、清零次数 |
| `production_summary` | 每设备、配置版本、生产日期、班次；班次索引-1表示整日汇总 |
| `production_backfill` | 每设备最近一次历史回算任务、进度和状态 |
| `production_migration` | 一次性历史数据迁移的完成标记 |

完整班次/生产日读取汇总；任意范围读取完整分钟及边界读数。超过24小时的缺口不展开为海量分钟记录，查询从增量明细补入。周、月读取生产日汇总。设备删除时扩展记录随外键级联清理；不提供按时间自动删除明细，避免缩减历史查询精度。容量规划需计入每设备每天约43,200条计数读数以及原有ThingsBoard遥测存储。

## 历史与导出

历史起止时间、配置生效日期和班次开始时间使用应用内日历/时间选择器，点击输入框或右侧图标即可选择；也保留手动输入，班次时间支持 `HH:mm`。查询与回算仍按设备配置时区解释所选日期时间。

新采集自动统计。历史页面的“回算已有遥测”按选定范围导入仍保留的原始 `totalCount`，每次最多31天；后台分页处理，并读取范围前后的边界读数。重复回算防重，失败后可重试；原始遥测已过期或未上报的区间无法恢复。单节点同时最多两个任务。任务无进展超过5分钟显示中断，可重新执行。

历史查询每次最多366天，可按生产日/班次和历史班次顺序筛选。结果分页只影响展示，Excel/CSV导出包括完整结果，以及查询范围、实际时段、单位、数据状态、清零次数和数据截止时间。速度曲线使用原有时序遥测，按至少1分钟的间隔取均值；区间数不超过 `min(1440, database.ts_max_intervals)`，范围较长时自动增大间隔。平台默认上限700，可通过 `DATABASE_TS_MAX_INTERVALS` 调整，普通看板和匿名大屏均遵守实际配置。界面轮询仍为5秒，聚合间隔与刷新频率不同。
